# 设计文档规范

## 概述

设计文档记录系统的架构决策、模块划分和接口定义。

## 文件位置

设计文档存储在 `docs/design/` 目录下。

## Issue 对应关系

每个设计文档被 Story/Epic Issue 的描述中引用：
- Issue description 中写 `→ docs/design/xxx.md`
- 设计文档的详细内容全部在 markdown 文件中
- 设计文档的版本号在文件头部维护

## 文件结构

```markdown
---
version: "1.0.0"
created: "2026-06-01"
updated: "2026-06-01"
---

# 设计文档标题

## 版本历史

| 版本 | 日期 | 变更说明 |
|---|---|---|
| 1.0.0 | 2026-06-01 | 初始版本 |

## 架构概述
[高层架构图和描述]

## 模块设计

### 模块名
- 职责
- 接口
- 依赖

## 数据模型
[核心实体关系]

## API 设计
[关键接口定义]

## 非功能性要求
- 性能
- 安全
- 可扩展性
```

## 版本管理

- 使用 `v{MAJOR}.{MINOR}.{PATCH}` 语义化版本
- MAJOR 更新：架构级变更，需归档旧版
- MINOR 更新：模块级变更，更新版本号
- PATCH 更新：文字修正、细节补充

## 归档规则

MAJOR 版本更新时，将旧版文件移至 `docs/design/archive/` 目录。

## 长度控制

建议单篇设计文档 1000-2000 行。超出时按模块拆分为多篇。
