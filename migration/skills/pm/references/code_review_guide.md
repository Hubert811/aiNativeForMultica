# 代码审查指南

## 原则

代码审查是质量保障的关键环节。

## 审查清单

### 功能性
- [ ] 代码实现是否符合 AC
- [ ] 边界条件是否处理
- [ ] 错误处理是否完善

### 代码质量
- [ ] 函数职责单一
- [ ] 变量命名清晰
- [ ] 无明显性能问题
- [ ] 无安全风险（SQL 注入、XSS 等）

### 测试
- [ ] 单元测试覆盖率是否足够
- [ ] 测试命名是否表达意图
- [ ] 是否有 mock 过度使用的情况

### 规范
- [ ] 遵循项目目录结构
- [ ] Commit message 包含 Story ID
- [ ] 无不必要的文件变更

## 审查流程

1. 开发者将 Issue 改为 `in_review`
2. 审查者在 PR 中留下评论
3. 审查通过后，Issue 改为 `done`
4. 审查不通过，Issue 改回 `in_progress`

不需要额外的状态同步操作。
